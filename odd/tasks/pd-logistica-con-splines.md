# PD logistic regression with splines

## Objective
Move the spline experiment of DEC-013 into `Notebooks/05_Modelizacion Clasificacion PD.ipynb` (with explanatory
markdown) and fix `n_knots=8`, `C=10**-0.5` in production (`07_despliegue/01_reentrenamiento.py`).

## Problem
The linear Ridge logistic over-predicts PD at both risk extremes (decile 0: 6.1% predicted vs 4.6% real).
An experiment kept in a temporary directory showed that `SplineTransformer` on 4 variables fixes it
(external Gini 0.416 -> 0.423, decile 0 calibration 4.2% vs 4.1%). The evidence is not in the repo yet.

## Scope
- In: notebook 05 (new challenger section, final model = splines), `01_reentrenamiento.py` PD pipeline and
  artefact version, `decisions.md` (DEC-013 status and integration evidence).
- Out: EBM as a dependency (discarded in DEC-013), boosting, API contract, notebooks 04 and 08.
- Do not touch: pending user changes in `RATING_ORDER` (01_reentrenamiento.py), notebooks 04 and 08.
  They stay unstaged and out of every commit made here.

## Constraints
- Splines apply to `yj__principal`, `yj__dti`, `yj__imp_cuota`, `ss__tipo_interes` only, inside the Pipeline
  (no leakage), `SplineTransformer(degree=3, knots='quantile', include_bias=False, n_knots=8)`.
- Production fixes `n_knots=8` and `C=10**-0.5`, `l1_ratio=0`; no grid in reentrenamiento.
- No new dependency in production. EBM in the notebook is optional (guarded import) and uses fixed params.
